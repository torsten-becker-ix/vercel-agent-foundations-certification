# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (see `pnpm-lock.yaml`).

- `pnpm dev` — start the Next.js dev server on http://localhost:3000
- `pnpm build` — production build
- `pnpm start` — serve the production build
- `pnpm lint` — ESLint 9 flat config, `--max-warnings 0` (see *Strictness* below). Vendored code (`components/ui/**`, `components/ai-elements/**`, shadcn hooks) is ignored. Prefix intentionally unused bindings with `_`.
- `pnpm typecheck` — `tsc --noEmit` (strictest compiler flags, see below)
- `pnpm test` / `pnpm test:watch` — Vitest (`vitest.config.mts`, Node environment, `@/` alias). Tests live next to the code as `*.test.ts(x)`. `server-only` is stubbed in tests.
- `pnpm format` / `pnpm format:check` — Prettier (`.prettierrc.json`, with `prettier-plugin-tailwindcss` for class order). Vendored code and `*.md` are ignored (`.prettierignore`).
- `pnpm check` — format check + lint + typecheck + test. **Run before every commit.**

## Strictness

The rule is the strictest available setting. Anything weaker must be listed under *Strictness exceptions* with a reason.

**TypeScript** (`tsconfig.json`): `strict` plus `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters`, `noUncheckedSideEffectImports`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `allowUnreachableCode: false`, `allowUnusedLabels: false`, `checkJs`.

- Environment variables are typed in `env.d.ts`, so `process.env.X` dot access works under `noPropertyAccessFromIndexSignature`. Add new vars there and in `.env.example`.
- Optional fields in **input/param** types are written `x?: T | undefined`, so callers can pass zod-parsed optionals under `exactOptionalPropertyTypes`.
- Open string unions with autocomplete: `Slug | (string & {})`.

**ESLint** (`eslint.config.mjs`):
- `eslint-config-next` core-web-vitals + typescript
- typescript-eslint **`strictTypeChecked` + `stylisticTypeChecked`** (type-aware, `projectService`)
- **`jsx-a11y` strict**
- `eslint-comments` (every `eslint-disable` needs a `-- reason`; unused disables are errors)
- extras: `no-explicit-any`, exhaustive `switch`, `strict-boolean-expressions`, `consistent-type-imports/exports`, `prefer-readonly`, `promise-function-async`, `require-array-sort-compare`, `react/jsx-no-leaked-render`, `react/no-array-index-key`, `eqeqeq`, `no-console` (warn/error allowed), `no-param-reassign`

### Strictness exceptions

| Exception | Reason |
| --- | --- |
| **TypeScript 6.0.x, not 7.x** | typescript-eslint 8 supports `typescript <6.1`; TS 7 (native compiler) would break type-aware linting. Upgrade once typescript-eslint supports it. |
| **ESLint 9, not 10** (npm marks 9 deprecated) | `eslint-config-next` 16's plugins (import, jsx-a11y, react) don't support ESLint 10. |
| `skipLibCheck: true` | Type errors inside third-party `.d.ts` files are outside our control (Next.js default). Our own code is fully checked. |
| Vendored `components/ui/**`, `components/ai-elements/**`, `hooks/use-mobile.ts`, `hooks/use-toast.ts` are not linted | Generated by the shadcn / AI Elements CLIs; restyling them would be lost on regeneration. They **are** type-checked with the strict flags; type-only fixes were applied (`exactOptionalPropertyTypes`, `type` imports, index-signature access). Re-check after regenerating. |
| `*.mjs` config files are not type-checked (linted without type info) | Their plugins ship no types (`eslint-plugin-jsx-a11y`, `postcss-load-config`). `vitest.config.mts` is type-checked. |
| `strict-boolean-expressions`: `allowNullableBoolean: true`, `allowString: true` (default) | `if (disabled)` on an optional boolean, and truthiness of a non-nullable string (= non-empty), are unambiguous. Nullable strings, numbers and objects must be compared explicitly. |
| `lib/api.ts` request helpers trust the API response type (return-type-only generics, one inline disable) | The response types mirror the store's OpenAPI spec. Runtime validation (zod) happens at the agent tool boundary, where the data reaches the model. |
| `notifyReturnInProcess` uses `console.log` and is `async` without `await` (inline disables) | Intentional stand-in for an email-provider call, provided by the starter. |
| Not enabled: `explicit-function-return-type`, `explicit-module-boundary-types`, `naming-convention` | Style only, not safety. They fight React/Next conventions (components, route handlers) and the API's field names; strict TS already checks the inferred types. |
| `components/agent-chat.tsx`: `WorkflowChatTransport` is cast to `ChatTransport` | Typing conflict between two Vercel packages under `exactOptionalPropertyTypes` (`@ai-sdk/workflow` declares `messageId?: string`, `ai` passes `string \| undefined`). Runtime contract identical; re-check on upgrades. |
| `lib/chat-types.ts`: `Record<never, never>` data parts (inline disable of `no-generated-empty-object-type`) | Intentionally no custom data parts; it keeps the message-part union closed, so `switch` statements stay exhaustive. |
| `@typescript-eslint/no-deprecated` disabled for `needsApproval` in `lib/tools.ts` | `ai` deprecates tool-level `needsApproval` in favour of call-level `toolApproval`, but `WorkflowAgent` documents tool-level `needsApproval` as its approval mechanism (`node_modules/ai/docs/03-agents/07-workflow-agent.mdx`). |
| `react/no-array-index-key` disabled once in `components/shopping/chat-message.tsx` | Message parts are append-only and have no ids. |
| Prettier ignores `*.md` | `CLAUDE.md` is partly rewritten by `next dev`; `README.md` is written once just before submission. |

## Environment

`.env.local` (gitignored) holds:

- `BYPASS_SECRET` — required. Sent as the `x-vercel-protection-bypass` header on every API call. Must never be exposed to the client (no `NEXT_PUBLIC_` prefix).
- `API_BASE_URL` — optional. Defaults to `https://vercel-agentic-swag-store-api.vercel.app/api` in `lib/api.ts`.

- `VERCEL_OIDC_TOKEN` — AI Gateway auth, written by `vercel env pull .env.local`; expires after 12 h.
- `TOOL_APPROVAL_SECRET` — required for returns. HMAC key that signs tool approval requests (≥ 32 random bytes, `openssl rand -base64 48`). Locally in `.env.development.local`; on Vercel as **Sensitive** for Production + Preview.
- `RETURN_FLOW_FAULT` — dev only, never on Vercel. `file-once` makes the return workflow's filing step fail on its first attempt, to demonstrate that completed side effects are not repeated.
- `AI_GATEWAY_API_KEY` — optional alternative to OIDC. Keep it in `.env.development.local`, because `vercel env pull` overwrites `.env.local`.

`.env.example` is the redacted template for new developers.

### Agents and workflows

- `withWorkflow` (`next.config.mjs`) generates `app/.well-known/workflow/v1/*` (git-ignored by its own `.gitignore`) and a `.swc/` cache; both are excluded from ESLint/Prettier. Don't add `.well-known/workflow` to the `proxy.ts` matcher.
- `pnpm-workspace.yaml`: `allowBuilds` for `@swc/core`, `esbuild`, `cbor-extract` (needed by `workflow`, pnpm 12 blocks install scripts otherwise), plus `minimumReleaseAgeExclude` for the pinned `ai@7.0.170` family. `overrides` pin fixed versions of transitive packages with security advisories (reasons in the file); `pnpm audit --prod` should only show `minimatch` (dev-only path).
- Model: `openai/gpt-oss-120b` for both agents, including the submission (free-tier Gateway credits exclude Anthropic models). One constant per agent.
- Model-specific code is tagged `gpt-oss workaround:` (`grep -rn "gpt-oss workaround" lib components app`). Review these when changing the model; add the tag to every new one.
- AI Gateway routing: `SHOPPING_AGENT_PROVIDER_OPTIONS` in `lib/agent.ts` restricts gpt-oss-120b to tested providers (Together AI broke tool-call parsing). Free-tier credits are rate-limited (429); the AI SDK retries those.
- Changing `lib/agent.ts` alone doesn't always rebuild the workflow bundle in dev ("Compiled workflows in 0ms"); `touch lib/workflows/chat-flow.ts` forces it.
- Adding AI Elements components: **don't** run `ai-elements` with flags (`--help` installs *everything*). Fetch `https://elements.ai-sdk.dev/api/registry/<name>.json`, write `files[].content` to its `target`, and replace `@/registry/default/ui/` with `@/components/ui/`. Then fix strict-mode type errors (type-only).
- Returns: `returnOrder` (tool, `needsApproval` = eligibility check, so impossible returns never get an approval card) → after Approve the next chat run starts `returnFlow` (`lib/workflows/return-flow.ts`) as its own workflow: lookup → notify → pre-authorize → file (with `createWebhook()` callback) → decision via webhook signal or polling `GET /returns/{id}` → notify. Approvals are HMAC-signed (`experimental_toolApprovalSecret`).
- Chat recovery (`lib/chat-storage.ts`, `components/agent-chat.tsx`): `localStorage` key `ship-it-shop:chat` holds the messages **as sent** plus the active run id, saved in the transport's `onChatSendMessage` and cleared in `onFinish`. It never holds the in-flight answer; that answer is rebuilt once by replaying the run from index 0.
  - Page refresh: `useChat({ messages, resume })`, with `resume` only when a run id is stored (an empty resume throws in `WorkflowChatTransport`). `prepareReconnectToStreamRequest` points the resume at `/api/chat/<runId>/stream`.
  - Connection lost (fetch fails while offline → `isDisconnect`): the `online` event or **Reconnect** remounts the session from storage, the same path as a refresh. Don't call `resumeStream()` in place: it would replay from 0 on top of the partial answer and duplicate it. And setting `resumeStreamIsReplay` would wipe the approval message on an approval continuation.
  - Drops while online are handled by the transport itself (`GET …/stream?startIndex=N`).
  - The server render starts empty; the client remounts with the saved chat (`useSyncExternalStore`), so there's no hydration mismatch.
  - In dev, StrictMode starts two resumes; the SDK cancels the first.
  - DevTools "Offline" doesn't cut a stream that's already open. Test drops with a `fetch` wrapper that errors the body (see `smoke-tests.md` §Recovery in the course notes).
- Inspect runs locally: `pnpm exec workflow inspect runs` / `pnpm exec workflow web`.

## Architecture

The storefront brand is **Ship It Shop** (metadata, header, homepage copy). The store is backed by the live **Vercel Swag Store API** (no local product/cart database). The protection-bypass secret stays server-side: every API read happens in a Server Component or Server Action, every cart mutation goes through a Server Action, and the cart token cookie is `httpOnly`.

### Data layer (`lib/`)

- `lib/types.ts` — pure type module re-exporting the API schemas (`Product`, `CartWithProducts`, `CartItemWithProduct`, `Promotion`, `Category`, `StockInfo`, `StoreConfig`). Both server and client modules import from here. Also exports the `CATEGORY_SLUGS` const tuple used by the category filter.
- `lib/api.ts` — typed `fetch` wrapper. Functions: `getProducts`, `getProductById`, `getProductStock`, `getCategories`, `getPromotion`, `getStoreConfig`, `cartCreate`, `cartGet`, `cartAdd`, `cartUpdate`, `cartRemove`. **Server-only**, enforced by `import "server-only"` (reads `process.env.BYPASS_SECRET`). Throws `ApiRequestError` on non-200/`success:false` responses.
- `lib/cart-token.ts` — `getOrCreateCartToken()`/`getCartToken()`/`clearCartToken()` using `next/headers`. Stores the API-issued cart UUID in an `httpOnly` cookie `cart_token` with a 30-day max-age.
- `lib/cart-actions.ts` — `'use server'` actions: `getCartAction`, `addToCartAction`, `updateCartItemAction`, `removeCartItemAction`, `getProductStockAction`. Each cart mutation calls the API and `revalidateTag('cart')`. The first add lazily creates the cart on the server.
- `lib/format.ts` — `formatPrice(cents, currency)` using `Intl.NumberFormat`. **API prices are integers in cents**, so always pass them through this helper.
- `components/cart-provider.tsx` — Client `CartProvider` that hydrates the cart on mount by calling `getCartAction()` (so the layout can stay synchronous and routes can be statically rendered). Mutations dispatch through Server Actions inside `startTransition`, with `useOptimistic` for snappy UI.

### Caching strategy

Classic App Router (Cache Components / `'use cache'` are intentionally **not** used).

- Read endpoints (`getProducts`, `getProductById`, `getCategories`, `getPromotion`, `getStoreConfig`) pass `next: { revalidate: 300, tags: [...] }` to `fetch`. Tags: `products`, `product:{id}`, `categories`, `promotion`, `store-config`.
- `getProductStock` uses `cache: 'no-store'` so the indicator reflects live inventory.
- All cart endpoints use `cache: 'no-store'`. Mutations call `revalidateTag('cart')`, primarily for navigation re-renders — same-page UI relies on the action's return value + `useOptimistic`.

### Routes (App Router)

- `/` (`app/page.tsx`) — **Static** (`○`). Synchronous parent component renders three siblings (`<PromoBanner />`, `<FeaturedProducts />`, `<CategoryShowcase />`) so async children fan out in parallel. Each handles its own data fetch.
- `/search` (`app/search/page.tsx`) — **Dynamic** (`ƒ`, by necessity — uses `searchParams`). Reads `q` and `category`, fetches categories + products in parallel via `Promise.all`, and renders results inline (no `Suspense`). Loading feedback is a spinner inside `<SearchForm />` driven by `useTransition`.
- `app/search/search-form.tsx` — Client. `next/form` `<Form>` for the no-JS fallback, debounced 300ms `router.replace` wrapped in `startTransition` once `q.length >= 3` (or back to empty), `<Select>` from shadcn for the category dropdown.
- `/products/[param]` (`app/products/[param]/page.tsx`) — **SSG** (`●`). The `param` accepts both product **id** and **slug** (the API resolves either). `generateStaticParams` enumerates products via `getProducts({ limit: 100 })`; `generateMetadata` builds title, description, and `openGraph`/`twitter` cards using `product.images`. The page renders product image, name, price, description server-side; the only client island is `<ProductPurchase />`.
- `app/products/[param]/product-purchase.tsx` — Client. Stock + qty selector + Add-to-Cart. Fetches stock on mount via `getProductStockAction`, polls every 30s. Initial render shows "Checking availability…" until the action resolves; this is the cost of keeping the product page statically renderable.
- `app/products/[param]/related-products.tsx` — Server, async. `getProducts({ category, limit: 8 })`, filters out the current product, slices to 4.

### Layout

`app/layout.tsx` is **synchronous** so it doesn't opt routes out of static rendering. It mounts `<Header />` (server) — which contains `<CartButton />` (client) — `<Footer />`, `<CartProvider>` (no initial cart prop; provider hydrates client-side), and `<CartSheet />`. `metadataBase`, `title.template`, and root `openGraph`/`twitter` defaults live here.

### Client / server split

Client components are kept minimal — only where state, effects, or browser APIs are required:
- `cart-provider.tsx`, `cart-button.tsx`, `cart-sheet.tsx` (cart state + UI)
- `app/products/[param]/product-purchase.tsx` (stock polling, qty, add-to-cart)
- `app/search/search-form.tsx` (input state + URL sync)

Everything else (`Header`, `Footer`, `ProductCard`, `ProductGrid`, `PromoBanner`, `CategoryShowcase`, `RelatedProducts`, every page) is a Server Component.

### Configuration quirks

- `next.config.mjs` no longer sets `typescript.ignoreBuildErrors` — type errors fail the build. `images.remotePatterns` is whitelisted for `**.public.blob.vercel-storage.com` and `**.vercel-storage.com` (where API product images live); add hostnames here if the API ever returns images from a new domain.
- `@vercel/analytics` only mounts when `NODE_ENV === 'production'` (see `app/layout.tsx`).
- The repo is linked to v0 (`https://v0.app/chat/projects/prj_X7UGePkFlLC33RuxWiTZySFDcSzO`); merges to `main` auto-deploy via Vercel. v0 may push commits directly. When deploying, set `BYPASS_SECRET` (and `API_BASE_URL`) in the Vercel project's environment variables.
- The root layout is intentionally synchronous so it doesn't opt routes out of static. `pnpm build` should report `/` as `○` (Static), `/products/[param]` as `●` (SSG), and `/search` as `ƒ` (Dynamic). If you ever convert the layout to `async function` and `await` something that uses `cookies()`/`headers()`/`searchParams`, you will silently switch every route back to dynamic — verify the build output after layout changes.
